## 문제 요약

정수 배열 `numbers`가 주어졌을 때, 각 원소의 오른쪽에 있는 수 중에서 **자신보다 크면서 가장 가까이 있는 수**를 찾는 문제이다.

이러한 수를 해당 원소의 **뒷 큰수**라고 한다. 뒷 큰수가 존재하지 않으면 `-1`을 저장한다.

예를 들어 다음 배열이 주어졌다고 하자.

```text
numbers = [2, 3, 3, 5]
```

각 원소의 뒷 큰수는 다음과 같다.

```text
2 → 3
3 → 5
3 → 5
5 → -1
```

따라서 정답은 다음과 같다.

```text
[3, 5, 5, -1]
```

## 핵심 포인트

- 단순 탐색으로 각 원소의 오른쪽을 모두 확인하면 최악의 경우 `O(N²)`이 걸린다.
- 스택에는 아직 뒷 큰수를 찾지 못한 원소의 **인덱스**를 저장한다.
- 현재 값이 스택 top의 값보다 크면, 현재 값이 스택 top 원소의 뒷 큰수이다.
- 조건을 만족하는 동안 스택에서 인덱스를 꺼내 정답을 갱신한다.
- 끝까지 스택에 남은 인덱스는 뒷 큰수가 없으므로 `-1`이 유지된다.

## 1) 단순 탐색의 문제점

가장 단순한 방법은 각 원소마다 오른쪽을 차례대로 탐색하면서 처음 만나는 더 큰 수를 찾는 것이다.

```java
for (int i = 0; i < numbers.length; i++) {
    for (int j = i + 1; j < numbers.length; j++) {
        if (numbers[i] < numbers[j]) {
            answer[i] = numbers[j];
            break;
        }
    }
}
```

이 방식은 이해하기 쉽지만, 배열이 내림차순으로 주어지는 경우 각 원소마다 오른쪽 끝까지 탐색해야 한다.

```text
[5, 4, 3, 2, 1]
```

따라서 최악의 경우 시간복잡도는 `O(N²)`이 되어 큰 입력을 효율적으로 처리하기 어렵다.

## 2) 단조 스택 접근

왼쪽부터 배열을 한 번만 순회하면서, 아직 뒷 큰수를 찾지 못한 원소들을 스택에 보관한다.

스택에는 값이 아니라 인덱스를 넣는다.

```java
Stack<Integer> st = new Stack<>();
```

현재 인덱스가 `i`일 때 다음 조건을 확인한다.

```java
numbers[st.peek()] < numbers[i]
```

현재 값 `numbers[i]`가 스택 top이 가리키는 값보다 크다면, 현재 값은 그 원소가 오른쪽에서 처음 만난 더 큰 수이다.

따라서 해당 인덱스를 스택에서 꺼내고 정답을 갱신한다.

## 3) 스택에 인덱스를 저장하는 이유

정답 배열의 특정 위치에 뒷 큰수를 저장하려면 원래 원소의 위치를 알아야 한다.

스택에 인덱스를 저장하면 다음 두 가지 작업을 모두 할 수 있다.

```java
numbers[st.peek()] // 스택 top 인덱스에 해당하는 값 확인
answer[st.pop()]  // 해당 인덱스의 정답 갱신
```

따라서 `(인덱스, 값)`을 함께 저장할 필요 없이 인덱스 하나만으로 값 비교와 정답 갱신이 모두 가능하다.

## 4) 현재 값이 스택 top보다 클 때 정답 갱신

현재 값이 여러 원소의 뒷 큰수가 될 수도 있으므로 `if`가 아니라 `while`을 사용한다.

```java
while (!st.isEmpty() && numbers[st.peek()] < numbers[i]) {
    answer[st.pop()] = numbers[i];
}
```

스택 top의 값이 현재 값보다 작은 동안 인덱스를 계속 꺼내고, 꺼낸 인덱스의 정답을 현재 값으로 갱신한다.

비교가 끝나면 현재 인덱스도 아직 자신의 뒷 큰수를 찾지 못한 상태이므로 스택에 넣는다.

```java
st.push(i);
```

같은 값은 더 큰 수가 아니므로 `<=`가 아니라 `<`로 비교해야 한다.

## 동작 원리

다음 배열을 예로 들어 보자.

```text
numbers = [2, 3, 3, 5]
```

### `i = 0`, 현재 값 `2`

스택이 비어 있으므로 인덱스 `0`을 넣는다.

```text
stack = [0]
```

### `i = 1`, 현재 값 `3`

스택 top의 값 `2`보다 현재 값 `3`이 크다.

인덱스 `0`을 꺼내고 `answer[0]`을 `3`으로 갱신한다.

```text
answer = [3, -1, -1, -1]
stack = [1]
```

### `i = 2`, 현재 값 `3`

스택 top의 값과 현재 값이 모두 `3`이므로 뒷 큰수 조건을 만족하지 않는다.

현재 인덱스 `2`를 스택에 넣는다.

```text
stack = [1, 2]
```

### `i = 3`, 현재 값 `5`

현재 값 `5`는 스택에 쌓인 두 `3`보다 모두 크다.

인덱스 `2`와 `1`을 차례대로 꺼내 각각의 정답을 `5`로 갱신한다.

```text
answer = [3, 5, 5, -1]
stack = [3]
```

순회가 끝난 뒤 스택에 남아 있는 인덱스 `3`은 오른쪽에서 더 큰 수를 만나지 못했다.

정답 배열을 처음부터 `-1`로 채웠기 때문에 별도의 후처리를 하지 않아도 `answer[3]`은 `-1`로 유지된다.

```java
Arrays.fill(answer, -1);
```

## 전체 코드

```java
package programmers.lv2.p154539;

import java.util.Arrays;
import java.util.Stack;

public class p154539 {
    public int[] solution(int[] numbers) {
        int[] answer = new int[numbers.length];
        Arrays.fill(answer, -1);
        Stack<Integer> st = new Stack<>();

        for (int i = 0; i < answer.length; i++) {
            while (!st.isEmpty() && numbers[st.peek()] < numbers[i]) {
                answer[st.pop()] = numbers[i];
            }

            st.push(i);
        }

        return answer;
    }

    public static void main(String[] args) {
        p154539 p = new p154539();
        int[] numbers1 = {2, 3, 3, 5};
        int[] numbers2 = {6, 1, 5, 3, 7, 2};
        System.out.println(Arrays.toString(p.solution(numbers1)));
        System.out.println(Arrays.toString(p.solution(numbers2)));
    }
}
```

## 시간복잡도와 공간복잡도

### 시간복잡도: `O(N)`

반복문 안에 `while`문이 있지만 각 인덱스는 스택에 한 번 push되고 최대 한 번 pop된다.

따라서 전체 연산 횟수는 배열의 길이에 비례하며 시간복잡도는 `O(N)`이다.

### 공간복잡도: `O(N)`

최악의 경우 모든 인덱스가 스택에 저장될 수 있다.

예를 들어 배열이 내림차순이면 순회가 끝날 때까지 pop되는 인덱스가 없으므로 스택의 크기는 최대 `N`이 된다. 따라서 정답 배열을 제외한 추가 공간복잡도는 `O(N)`이다.

## 정리

이 문제의 핵심은 스택에 **아직 뒷 큰수를 찾지 못한 원소의 인덱스**를 저장하는 것이다.

현재 값이 스택 top의 값보다 크면 현재 값으로 정답을 갱신하고, 끝까지 스택에 남은 인덱스는 뒷 큰수가 없으므로 초깃값 `-1`을 그대로 유지한다.

단조 스택을 이용하면 중복 탐색을 제거하여 `O(N²)`의 단순 탐색을 `O(N)`으로 개선할 수 있다.
